Regna — Stack Setup
Installation complète
pnpm · Turborepo · Nuxt 4 · Fastify · Engine TS (@chess/engine)
1
Prérequis — installer pnpm
global
# via npm npm install -g pnpm
# vérifier pnpm --version
2
Monorepo racine
racine /
mkdir regna && cd regna pnpm init pnpm add -D turbo typescript mkdir -p packages/engine apps/client apps/server
pnpm-workspace.yaml
packages: - "packages/*" - "apps/*" # Optional (pnpm): allow native dependency builds during install allowBuilds: "@parcel/watcher": true esbuild: true
turbo.json
{ "tasks": { "build": { "dependsOn": ["^build"], "outputs": ["dist/**"] }, "dev": { "cache": false, "persistent": true }, "typecheck": {} } }
package.json — racine
{ "name": "Regna", "packageManager": "pnpm@11.1.3", "scripts": { "dev": "turbo run dev", "build": "turbo run build", "typecheck": "turbo run typecheck" }, "devDependencies": { "turbo": "...", "typescript": "..." } }
Éviter la combinaison packageManager + devEngines.packageManager : Turborepo 2.x ignore alors le premier et échoue avec « Missing packageManager » / problèmes de workspaces.
3
packages/engine — moteur de règles
@chess/engine
cd packages/engine pnpm init pnpm add zod pnpm add -D typescript npx tsc --init --strict --target ES2022 --module NodeNext --moduleResolution NodeNext --outDir dist
package.json
{ "name": "@chess/engine", "version": "1.0.0", "type": "module", "main": "./dist/index.js", "scripts": { "dev": "tsc --watch", "build": "tsc" }, "dependencies": { "zod": "..." }, "devDependencies": { "typescript": "..." } }
Le champ "name" doit être exactement @chess/engine pour que les dépendances workspace:* se résolvent (le nom du dossier engine ne suffit pas).
C'est le package le plus important — moteur pur TS, sans dépendance UI ni serveur. Partagé entre client et server.
4
apps/server — Fastify + Socket.IO
apps/server
cd apps/server pnpm init pnpm add fastify fastify-plugin @fastify/cors socket.io drizzle-orm postgres zod "@chess/engine@workspace:*" pnpm add -D typescript tsx @types/node drizzle-kit
package.json
{ "name": "server", "type": "module", "scripts": { "dev": "tsx watch src/index.ts", "build": "tsc" }, "dependencies": { "@chess/engine": "workspace:*" } }
5
apps/client — Nuxt 4 + PixiJS
apps/client
# init Nuxt (choisir : minimal, pnpm, no git) pnpm dlx nuxi@latest init apps/client
# si pnpm bloque sur les scripts de build pnpm approve-builds
# packages cd apps/client pnpm add pixi.js @vueuse/core vue vue-router "@chess/engine@workspace:*" pnpm add -D @vite-pwa/nuxt
nuxt.config.ts
export default defineNuxtConfig({ modules: ['@vite-pwa/nuxt'], pwa: { manifest: { name: 'Regna', short_name: 'Regna', theme_color: '#3D5AFE' } } })
package.json — ajouter engine
{ "name": "client", "private": true, "dependencies": { "@chess/engine": "workspace:*" } }
⚠ Ne pas utiliser @nuxtjs/pwa — abandonné, incompatible Nuxt 4. Utiliser @vite-pwa/nuxt.
6
Install final & lancement
racine /
# depuis la racine — résout tous les workspaces # à la racine du monorepo (le dossier où se trouvent pnpm-workspace.yaml et package.json racine) pnpm install
# lancer tout en parallèle pnpm dev
# ou uniquement le client cd apps/client && pnpm dev
Pour un graphe workspaces cohérent, préférez pnpm install depuis la racine (pnpm peut aussi retrouver la racine depuis un sous-package, mais tous les manifests doivent rester synchronisés).
